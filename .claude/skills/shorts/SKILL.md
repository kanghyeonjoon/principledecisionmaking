# 쇼츠 추출 (원소스 멀티유즈)

롱폼 한 편으로 추가 유입 5갈래를 만든다. 기준: 15분 영상이면 5개, 30분이면 7~10개.

## 진행 순서

1. **재료 확인**: 자막(SRT) 파일이 기본 재료다. 다음 순서로 찾는다 (위에서부터 정확도 높음).
   - **편집 프로그램(프리미어 프로 등)에서 내보낸 SRT** — 편집을 프리미어에서 하는 사용자라면 이게 기본 경로다. SRT가 아직 없다면 내보내는 방법을 `docs/PREMIERE_SRT.md` 기준으로 안내하고 파일 경로를 받는다.
   - 그 외 SRT (whisper 등으로 이미 만들어 둔 것)
   - SRT가 없고 영상 파일만 있으면: `python3 scripts/whisper_subtitles.py <영상경로>`로 자막을 먼저 뽑고 진행한다 (whisper 미설치면 설치를 제안).
   - 대본 파일(`channel/plans/…-대본.md`)만 있으면 구간 **후보**까지만 잡는다 — 타임코드는 확정하지 않는다 (아래 주의 참조).

2. **쇼츠 구간 선정**: 다음 기준으로 독립 성립 구간을 고른다.
   - **맥락 없이 봐도 이해되는가** — 롱폼의 앞부분을 안 봤어도 완결된 이야기인가
   - **첫 3초 훅이 있는가** — 구간 안에 시선을 잡는 문장이 있거나, 앞에 붙일 훅을 만들 수 있는가
   - **길이 15~59초** (쇼츠는 60초 미만)
   - 숫자·반전·강한 주장·실수담이 있는 구간이 우선

3. **쇼츠 기획서 작성**: 각 쇼츠마다 정리한다.
   | 항목 | 내용 |
   |---|---|
   | 구간 | 시작–끝 타임코드 |
   | 훅 (첫 3초) | 화면에 크게 박을 문장 |
   | 제목 | 쇼츠용 제목 |
   | 세로 자막 | 짧은 리듬으로 끊은 자막 줄들 (한 줄 10자 안팎) |
   | 마지막 CTA | "풀영상은 채널에" 등 |
   
   저장: `channel/plans/YYYY-MM-DD-<주제>-쇼츠.md` + 잘라내기용 JSON(`channel/output/shorts_segments.json`, 형식: `[{"start": "00:01:23", "end": "00:02:10", "title": "훅문장"}]`)

4. **실제 클립 잘라내기** (영상 파일이 있고 사용자가 원하면):
   ```
   python3 scripts/shorts_cut.py <영상경로> --json channel/output/shorts_segments.json --vertical
   ```
   - `--vertical`: 가운데 기준 9:16 크롭 + 1080x1920. 화자가 화면 가운데 없는 영상이면 크롭 위치 문제를 미리 알려주고, 편집 프로그램에서 리프레임하는 걸 권한다.
   - ⚠️ SRT가 편집 완료본 기준이므로, 잘라낼 영상도 **같은 편집 완료본**(최종 내보낸 영상)이어야 시간이 맞는다. 원본 촬영 파일에 그 타임코드를 쓰면 엉뚱한 구간이 잘린다.
   - 결과: `channel/output/shorts/` 폴더

5. **마무리**: 각 쇼츠의 발행 순서를 제안한다 (훅이 가장 강한 것부터, 롱폼 발행 직후 2~3일 간격).

## 주의

- 롱폼의 결론을 통째로 스포일러하는 구간은 피한다 — 쇼츠는 예고편이자 미끼다.
- 구간 타임코드는 자막(SRT) 기준으로 잡는다. 대본만 보고 타임코드를 추정하지 않는다.
