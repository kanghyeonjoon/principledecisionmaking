# 대본 골격 추출 & 대본 작성

두 가지 모드가 있다. 상황을 보고 필요한 모드로 진행한다.

## 모드 A — 대본 골격 추출 (처음 한 번)

`channel/SCRIPT_STRUCTURE.md`가 없으면 먼저 이걸 만든다.

1. **재료 모으기** (가능한 방법 순서대로):
   - 사용자가 기존 대본 파일을 갖고 있으면 받아서 읽는다.
   - 없으면 `channel/videos.csv`에서 조회수 상위 영상들의 자동 자막을 받아온다:
     ```
     yt-dlp --write-auto-subs --sub-langs ko --skip-download --convert-subs srt -o "channel/output/subs/%(id)s" <영상URL>
     ```
   - 사용자에게 "시청지속률이 특히 좋았던 영상"이 뭔지 물어서 그 영상을 우선 분석한다 (조회수와 지속률은 다르다).

2. **공통 골격 추출**: 잘된 대본 3~5개에서 공통 구조를 뽑는다.
   - 첫 8초에 뭘 하는가 / 약속을 어떻게 하는가 / 본문이 몇 개 단위로 쪼개지는가 / 전환 문구 / 마무리와 CTA 패턴
   - **말투 특징**: 자주 쓰는 표현, 추임새, 문장 길이, 존댓말 여부 — 실제 문장을 예시로 채집한다.

3. **저장**: `templates/SCRIPT_STRUCTURE_TEMPLATE.md` 양식으로 `channel/SCRIPT_STRUCTURE.md`에 저장.

## 모드 B — 새 대본 작성 (기획안 → 대본 자동 연결)

기획안이 있으면 사용자가 파일명을 몰라도 알아서 찾아 이어받는 게 이 모드의 핵심이다.

1. **기획안 자동 연결**:
   - `channel/plans/`에서 기획안 파일을 찾는다. 접미사가 붙은 파일(`-대본.md`, `-답변.md`, `-쇼츠.md`, `-SEO.md` 등)은 산출물이므로 제외.
   - 이미 `-대본.md`가 있는 기획안도 제외하고, **가장 최근 날짜의 기획안**을 고른다.
   - 후보가 2개 이상이거나 사용자가 말한 주제와 다르면, 목록을 보여주고 고르게 한다.
   - 기획안이 하나도 없으면: `/video-plan`부터 하는 걸 권한다. 그래도 진행을 원하면 주제·타겟·예상 길이만 물어보고 진행한다 (품질 차이가 크다는 것을 한 번 언급).

2. **기준 로드**: `channel/SCRIPT_STRUCTURE.md`(구조), `channel/BRAND.md`(톤), 그리고 1번에서 고른 기획안을 읽는다.
   - SCRIPT_STRUCTURE.md가 없으면 모드 A를 먼저 하자고 권한다 (없이도 진행은 가능).
   - 기획안에서 뽑아 쓸 것: **인터뷰 질문 6개, 인트로 30초, 본문 골격, 예상 길이, 썸네일·제목이 한 약속**.

3. **재료(답변) 받기**: 인터뷰 질문 6개에 사용자가 답한 내용(녹음→텍스트)을 확보한다.
   - 먼저 `channel/plans/<기획안이름>-답변.md`가 있는지 확인한다. 있으면 그걸 쓴다.
   - 없으면 사용자에게 요청한다: "기획안의 질문 6개에 말로 답한 걸 녹음해서 텍스트로 붙여넣어 주세요. 순서 안 지켜도 되고, 두서없어도 됩니다."
   - **채팅으로 받은 답변은 반드시 원문 그대로 `channel/plans/<기획안이름>-답변.md`에 먼저 저장**한 뒤 작업한다. 이 원문이 사용자의 진짜 말투 자료이므로 다듬지 말고 보존한다.
   - 답변이 부실한 질문이 있으면 대본 쓰기 전에 그 부분만 다시 물어본다.

4. **대본 작성**: `templates/SCRIPT_TEMPLATE.md` 양식으로 쓴다.
   - SCRIPT_STRUCTURE.md의 골격을 그대로 유지하고 내용만 새 주제로 채운다.
   - **답변 원문이 대본의 뼈와 살이다.** 사용자의 실제 경험·숫자·사례·표현을 최우선으로 살린다.
   - 사용자의 말투(SCRIPT_STRUCTURE.md에 채집해 둔 실제 표현 + 답변 원문의 말버릇)를 쓴다. AI 문어체 금지 — 소리 내서 읽었을 때 자연스러운 구어체.
   - 첫 8초 훅과 30초 약속은 기획안의 인트로를 발전시킨다. 썸네일·제목과 같은 약속이어야 한다.
   - 화면·자막 지시는 `[대괄호]`로 쓴다. 쇼츠로 독립될 수 있는 구간은 섹션 제목에 🎬 표시 (나중에 /shorts가 이 표시를 먼저 본다).

5. **길이 검증**: 초안을 `channel/plans/<기획안이름>-대본.md`로 저장한 뒤 러닝타임을 확인한다.
   ```
   python3 scripts/script_timer.py channel/plans/<기획안이름>-대본.md
   ```
   - 기획안의 예상 길이 대비 ±10%를 넘으면 늘리거나 줄이고, 맞을 때까지 다시 확인한다.
   - 결과 표(섹션별 타임코드)를 사용자에게 보여준다 — 촬영할 때 진행표가 된다.

6. **저장 + 상태 업데이트**:
   - 대본: `channel/plans/<기획안이름>-대본.md`
   - 기획안 머리말의 상태를 `기획`에서 `촬영대기`로 바꾼다.
   - `channel/CALENDAR.md`가 있으면 해당 영상의 단계도 '촬영대기'로 옮길지 물어본다.

7. **검수 안내**: "소리 내서 한 번 읽어보시고, 입에 안 붙는 문장을 알려주시면 고쳐 드려요. 다음 단계는 촬영이고, 찍고 나면 /cut-edit로 이어집니다."

## 주의

- 사용자가 준 경험·숫자를 지어내서 보태지 않는다. 비어 있는 부분은 사용자에게 물어본다.
- 답변 원문(`-답변.md`)은 다듬지 않고 그대로 보존한다. 대본만 다듬는다.
- 대본 길이는 기획안의 예상 길이에 맞춘다 (한국어 기준 말하기 속도 분당 약 300자, script_timer.py로 확인).
- BRAND.md의 금지 목록에 걸리는 표현은 쓰지 않는다.
